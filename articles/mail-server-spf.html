Mail Server 安全機制 · #SPF

Mail Server 安全機制－SPF 寄件者來源管理規則

SPF（Sender Policy Framework）讓收件端郵件伺服器依據郵件中的寄件者網域，主動向寄件端所屬的 DNS 伺服器核對其 SPF 記錄，再依比對結果決定接收、歸入垃圾郵件或拒絕接收。

#MailPlus#SPF

01SPF 的運作方式

SPF 的主要目的：避免他人冒用您的網域名稱寄信。

收件端郵件伺服器依比對結果處理郵件：

pass

傳送到使用者收件匣

寄件 IP 屬於該網域在 SPF 記錄中宣告的來源。

soft fail

傳送至垃圾郵件匣

寄件 IP 不在 SPF 記錄中，但網域設定為 ~all。

hard fail

拒絕傳送

寄件 IP 不在 SPF 記錄中，且網域設定為 -all。

02SPF 記錄語法

設定 SPF 的方式，是在網域名稱的 DNS Server 中加入一筆 TXT 記錄，語法如下：

語法 v=spf1 [a] [mx] [a:<domain>] [mx:<domain>] [ip4|ip6:<IP address>] <enforcement rule>
v=spf1

必要的宣告，表示此記錄為 SPF version 1。

a

比對 DNS 中的 A 記錄；若未指定網域名稱，則以目前的網域為主。

mx

比對 DNS 中的 MX 記錄；若未指定網域名稱，則以目前的網域為主。

a: / mx:
domain name

通常為含有 FQDN 完整名稱的 Mail Server 寄件伺服器名稱，尤其是代為寄信機構的寄信伺服器 FQDN。

ip4: / ip6:

直接指定允許寄信的 IP 位址；ip4 為 IPv4 格式，ip6 為 IPv6 格式。

-all / ~all

強制規則：決定不在 SPF 記錄中的寄信 IP 應如何處理，詳見下節。

03強制規則：-all 與 ~all

-allHard Fail

不在 SPF 記錄中的寄信 IP，一律視為偽造 IP。

建議：公司僅使用 SPF 機制，且確定只有記錄中的 IP 會寄信時使用。

~allSoft Fail

不確定是否只有 SPF 清單上的寄信伺服器 IP 會寄信，不直接拒收。

建議：同時使用 DKIM 及 DMARC 機制的企業使用，由後兩者進一步驗證。

搭配 DKIM 與 DMARC

SPF 驗證寄件來源 IP，DKIM 驗證郵件內容未遭竄改，兩者互補；再搭配 DMARC 指定驗證失敗時的處理方式，可完整防範網域遭到冒用。

04範例解析

"v=spf1amxa:hongku.twmx:mail.hongku.twip4:114.34.160.46-all"
  1. v=spf1：宣告為 SPF version 1。
  2. a、mx：允許目前網域的 A 記錄與 MX 記錄所對應的 IP 寄信。
  3. a:hongku.tw：允許 hongku.tw 的 A 記錄所對應的 IP 寄信。
  4. mx:mail.hongku.tw：允許 mail.hongku.tw 的 MX 記錄所對應的 IP 寄信。
  5. ip4:114.34.160.46：允許此 IPv4 位址寄信。
  6. -all：除上述來源外，其餘寄信 IP 一律視為偽造（Hard Fail）。
