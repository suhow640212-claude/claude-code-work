Mail Server 安全機制 · #DMARC

Mail Server 安全機制－DMARC（以網域為基礎的郵件驗證、報告和一致性）

DMARC 搭配寄件者原則架構（SPF）與網域金鑰識別郵件（DKIM）來驗證郵件寄件者，確保目的地電子郵件系統信任您網域傳送的郵件，並提供額外保護，防範詐騙與網路釣魚電子郵件。

#MailPlus#DMARC

01DMARC 的角色

SPF 與 DKIM 負責驗證；DMARC 則協助收件方郵件系統決定，如何處理未通過 SPF 或 DKIM 檢查的您網域傳送的郵件。

SPF

驗證寄件來源 IP

寄件 IP 是否為網域宣告允許的寄信來源。

DKIM

驗證郵件未遭竄改

以公鑰驗證郵件標頭的簽章。

DMARC

決定驗證失敗時的處理方式，並回報結果

由網域擁有者宣告政策（無、隔離、拒絕），收件端依政策處理可疑郵件，並定期將匯總報告寄回給網域擁有者。

02DMARC 政策的三種處理方式

DMARC 記錄中的 p 參數決定處理可疑電子郵件的方式：

p=none

無

不對郵件採取任何處置，僅將可疑郵件記錄於每日報告中。

僅監控
p=quarantine

隔離

將郵件標示為垃圾郵件，並移至收件者的垃圾郵件資料夾中，收件者可以查看自己的垃圾郵件。

中度
p=reject

拒絕

要求收件伺服器拒絕郵件，導致 SMTP 拒收郵件並將郵件退回給寄件伺服器。

03設定步驟

1

啟動 DMARCMailPlus Server › 安全性 › 認證

於 安全性 › 認證 頁面的 DMARC 區塊勾選 啟動 DMARC。

2

於 DNS Server 新增 TXT 記錄DNS Server › 轄區管理 › 編輯 › 資源記錄 › 新增 › TXT

開啟 Synology DNS Server，於轄區管理編輯網域，新增一筆 TXT 記錄：

名稱_dmarc
資訊"v=DMARC1; p=none; rua=mailto:service@hongku.tw"
v=DMARC1宣告為 DMARC 記錄。
p=none政策為「無」：不對郵件採取任何處置，僅記錄於每日報告中。
rua=mailto:service@hongku.tw每日匯總報告的收件信箱。

建議

初次導入可先使用 p=none，透過每日報告確認自家郵件皆能通過 SPF 與 DKIM 驗證後，再逐步調整為 p=quarantine 或 p=reject，以免正常郵件被誤判。
